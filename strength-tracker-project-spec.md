# Strength Tracker — описание проекта

## Идея

Веб-приложение для трекинга силовых тренировок в зале. Решает конкретную проблему: бумажный блокнот неудобно носить, а в заметках телефона нельзя однозначно привязать запись к конкретному тренажёру ("3 подхода по 20кг на бицепс" — на каком именно тренажёре, непонятно, если в зале их несколько похожих).

**Решение:** пользователь фотографирует тренажёр в зале, фото становится обложкой карточки, внутри карточки копится история подходов по датам — вес, повторения, номер подхода.

Приложение используется только с телефона, прямо в зале, между подходами.

---

## Архитектура

Классическая трёхзвенная схема:

```
Фронтенд (браузер) → API-запрос → Бэкенд → База данных
                                          → Хранилище фото
```

- **Фронтенд** — то, что видит пользователь, отправляет запросы на бэкенд, сам никогда не трогает базу данных напрямую
- **Бэкенд** — проверяет права доступа, обрабатывает логику, решает что писать в базу и куда сохранять фото
- **База данных** — хранит структурированные данные (тренировки, веса, подходы)
- **Хранилище фото** — отдельно от базы данных, потому что файлы тяжёлые; в базе хранится только ссылка на файл

## Технологический стек (MVP)

| Слой | Технология |
|---|---|
| Бэкенд | Go + Gin или Echo |
| Работа с БД | sqlx / pgx (сырой SQL, не ORM — для лучшего понимания базы) |
| База данных | PostgreSQL |
| Хранилище фото | Файловая система сервера или облако (Cloudinary) |
| Авторизация | email + пароль, JWT-токены (`golang-jwt/jwt`) |
| Фронтенд | HTML/CSS/JS, мобильная вёрстка (без десктоп-адаптации на этапе MVP) |

**Осознанно отложено на потом:** кэширование, эксперимент с MongoDB, микросервисы — эти темы вернутся отдельными итерациями поверх работающего MVP, когда будет что сравнивать и ускорять.

## Модель данных

Пять таблиц, связь строится вокруг промежуточной таблицы `workout_items`, потому что один тренажёр встречается во многих тренировках, а одна тренировка содержит несколько тренажёров (связь "многие ко многим").

**users**
- `id` (uuid, PK)
- `email`
- `password_hash`

**machines** — тренажёр
- `id` (uuid, PK)
- `user_id` (FK → users)
- `name`
- `photo_url`

**workouts** — тренировочный день
- `id` (uuid, PK)
- `user_id` (FK → users)
- `workout_date`

**workout_items** — связка "какой тренажёр был в этой тренировке"
- `id` (uuid, PK)
- `workout_id` (FK → workouts)
- `machine_id` (FK → machines)

**sets** — подход
- `id` (uuid, PK)
- `workout_item_id` (FK → workout_items)
- `set_number`
- `weight_kg`
- `reps`

## Экраны (MVP)

1. **Логин / регистрация** — email, пароль, переключатель между входом и регистрацией
2. **Список тренажёров (главный экран)** — сетка карточек (фото + название), плавающая кнопка добавления, нижняя навигация "Тренажёры / История"
3. **Добавление тренажёра** — кнопка "сделать фото" (главное действие), превью снимка, поле названия
4. **Карточка тренажёра (история)** — фото и название сверху, метка личного рекорда, подходы сгруппированы по дням (новые сверху)
5. **Добавление подхода** — дата (по умолчанию сегодня), вес, повторения, номер подхода (авто-инкремент), кнопка "сохранить и добавить ещё" — чтобы не выходить из формы между подходами подряд
6. **История тренировок** — список дат с summary (кол-во тренажёров и подходов), клик открывает детали дня

Макет всех экранов уже нарисован в Claude Design и утверждён — используется как визуальный референс при вёрстке.

## Визуальный стиль

- Тёмная тема, акцентный цвет — голубой `#2ecbff`
- Шрифты: Newsreader (заголовки), Instrument Sans (текст), Space Mono (цифры/данные) — тот же стиль, что и на сайте-визитке
- Mobile-first: крупные зоны нажатия, главные действия — в нижней трети экрана, под большой палец
- Десктопная адаптация в MVP не нужна — приложение используется только с телефона в зале

## Что откладываем на будущие итерации

- Кэширование
- Эксперимент с MongoDB на отдельном куске данных
- Графики прогресса по тренажёру

- Заметки к подходу
- Многопользовательский режим для друзей/подписчиков (сейчас — только сам пользователь)
- Десктопная адаптация вёрстки
- Обработка плохого интернета/оффлайн-режим в зале
